# 项目清理与模块化重构计划

状态：第一阶段进行中；第 1 批代码及依赖清理已验证，打包启动问题另批处理。

基线：`v1.0.0`，提交 `0eaa0bd`。本计划按“清理冗余 → 模块化拆分 → 目录结构整理”三个阶段执行，每个阶段完成验证后再进入下一阶段。

## 目标与边界

让项目更容易定位、修改和验证，同时保持现有功能、界面和数据兼容性。

- 保持 NOTE、TODO、CLIP、DESK 的内容保存、排序、撤销和窗口行为。
- 保持 WIDGETS、SETTINGS、COLORS 共用一个管理窗口，以及最右侧返回按钮。
- 保持最低 5% 透明度、方块主题、不占布局空间的悬浮滚动条。
- 保持三色取色、只读内置套装、自定义套装命名和编辑、套装身份及实时预览。
- 保持预览不入库，保存后应用，返回、关闭或切换页面后撤销未保存预览。
- 保持主进程独占数据库、renderer 通过 preload 访问业务数据的边界。
- 不在这次重构中升级框架、改变数据库结构、添加产品功能或调整界面文案。
- 不改写已有 Git 提交和 `v1.0.0` 标签，不操作用户正在使用的数据库。

按职责拆分，不以文件行数为唯一标准；没有独立职责的小片段不必单独建文件。优先保留现有工具和设计方式，不引入新的状态库、通用服务框架或依赖注入框架。

## 验证与完成标准

当前基线的类型检查、Lint、21 项数据库测试、迁移检查和 renderer 构建已通过。已有实际窗口验证覆盖配色预览及主题删除弹窗。Windows 完整打包曾遇到临时 `Pin.exe` 的访问或目录重命名错误，这不等于打包验证通过；涉及目录、原生依赖或配置的修改，仍需完成完整打包和启动验证，并记录环境阻碍。

常用检查：

```bash
pnpm typecheck
pnpm lint
pnpm test:db
pnpm db:check
pnpm start
pnpm package
```

按改动范围执行相关检查；每阶段结束执行完整检查，不为纯文档移动反复运行业务测试。

| 回归范围 | 核心检查 |
| --- | --- |
| 数据 | 旧迁移升级、重启恢复、级联删除、自定义套装身份 |
| 内容 | NOTE 自动保存；TODO 排序和完成分组；CLIP 复制、去重和上限；DESK 标签及内容隔离 |
| 窗口 | 拖动、缩放、折叠、置顶、隐藏、恢复、最低 5% 透明度、吸附和托盘 |
| 管理页面 | 共用窗口导航、最右返回按钮、设置保存、确认删除和撤销 |
| 配色 | 三色对应、只读内置套装、自定义命名和编辑、默认同步及独立配色 |
| 预览生命周期 | 连续取色、还原、保存、返回、原生关闭、切页和 reload；新窗口读取当前预览；临时颜色不入库 |
| 视觉 | 窄窗口无溢出、悬浮贴边滚动条不占空间、图标悬浮不高亮、确认弹窗跟随主题 |
| 发布 | Electron 原生依赖、迁移资源、preload 和 renderer 路径；多显示器及 DPI 作为已知专项回归单列记录 |

只调整文件组织不应宣称解决了已有的多显示器、DPI 或发布环境问题。发现功能缺陷时单独记录和提交，避免混入文件移动。

完成条件：三个阶段清单逐项更新；验证结果和未解决项有记录；现有功能与数据兼容；每个阶段均有可回退的提交。全部完成后再决定新的版本号和 tag，不在规划阶段提前标记版本。
